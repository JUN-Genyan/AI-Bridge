# 多会议室改造：结论和待续（2026-10-22）

用户要求：
1. 能同时打开多个会议室，设好工作护栏，防止修改同一文件；公告设为会议室的 goal；添加会话的 MCP / 技能 / 插件配置。
2. 尝试对整个 AI-Bridge 做架构优化，做成 MCP / exe / app。

## 已上线（2026-10-22 切换，8765 端口跑的就是新代码）

- **架构**：`roundtable.py` 只剩启动入口，代码拆进 `bridge\` 包，每场会议一个独立的 `Room`。结构见 README 的"代码结构"。
- **几场会议同时开**：
  - 各跑各的，"停"只停这场。
  - 页面左边栏是会议列表，标着"在想 / 等你 / 新 N"。
  - 地址栏 `?r=会议号`，每个标签页开一场。
  - 老的 5 场会议、附件都认得（已实测）。
- **目标**：原来的"公告"改叫"目标"，递给 AI 的说法也跟着改了，字段名没变。
- **文件护栏**（claude、codex 都实测挡住了）：
  - 改文件时自动占，一轮说完放开。
  - AI 用 bridge 的 `claim_files` 明着占。
  - 你在页面上"我在改…"占，也能强行放开。
  - claude 用 HTTP 钩子，codex 用 PreToolUse 钩子（要先过信任 hash）。
- **工具开关**：每场会议、每个 AI 各自设 MCP（只在干活模式加载）、插件、技能。
  - claude 带钩子的插件和 claude.ai 同步来的插件默认关。
  - codex 的插件只能整体开关。
- **会议室自己的 MCP**（`/mcp`）：
  - 会议里的 AI 用：看目标、中途发进度 / 文件、改看板、占文件。
  - 外面的 AI 用：列会议、读会议、往会议里发言。
- **装成 app**：PWA（manifest、service worker、图标、"会议室没开"提示页）。
- **测试**：11 个文件、91 个测试全过（每个文件单独跑：`python tests\test_xxx.py`）。

## 定下的做法和原因

- claude 不再用 `disableAllHooks`：它会连会议室自己的护栏钩子一起关掉。用户的钩子目前只来自插件，所以带钩子的插件在会议室里默认关。
- 目标照旧放在消息里递，不放系统提示：`--append-system-prompt` 在 `--resume` 时还是第一次那份，改了不生效。
- 没接 claude 的 `/goal`、codex 的 goal：两者都是"AI 自己一轮接一轮干到它认为达成"。codex 实测一设就自己开跑，还会多花轮次。
- 起 claude / codex 不经过 npm 的 `.cmd` 外壳：它会过一道 cmd.exe，参数里的 `|` 被当成管道。claude 直接起 `claude.exe`，codex 用 node 跑 `codex.js`。

## 待续 / 问题清单

1. **要不要做"目标模式（自动推进）"**：按会议打开后，codex 用 goal、claude 用 `/goal`，AI 自己干到目标达成，要设 token 预算。会多花额度，两个 AI 同时自动推进也可能互相打架。等用户定。
2. **exe**：没做。要装 PyInstaller（得用户同意），或者只给一个打包脚本。现在用桌面快捷方式加装成 app，已经能当程序用。
3. **codex 往 `~/.codex/config.toml` 写的信任**：测试时 codex 自己给几个临时目录写了 `[projects.'c:\users\27200\appdata\local\temp\rt_…'] trust_level = "trusted"`。要不要清，问用户。
4. **真会议里还没用过的**：
   - 两场会议同时干活、同一个仓库里撞同一个文件；
   - 手机上的会议列表和"等你"提醒；
   - 经 tailscale 的 https 装到手机主屏。
5. **护栏管不到命令行写文件**（`sed -i`、脚本）：规矩里写了不许绕，撤回清单也不记。以后可以考虑干活模式下每轮结束用 git 对比找出"没记录的改动"提醒一下。
